# How to Use This With Claude Code (the full-power version)

Hey Pops. This is the upgraded way to work on the book. Instead of uploading a file to a Project,
you open this whole folder inside **Claude Code**, and Claude can do everything right here: read
the book, search it, run your editors, and pull my latest updates so we are always working off the
same version.

Two ways to work, pick whichever you like:
- **Simple:** the Claude Project version (see `how-to-use-with-claude.md`). Upload one file, chat.
  No install. Great, but no built-in search and you'd re-upload to get my updates.
- **Full power (this page):** Claude Code. A little more to set up once, then it has search and
  stays in sync with my changes automatically.

You do NOT need to be technical. After the one-time setup, you just talk to Claude in plain English
or type a simple command like `/find`. If any of the setup feels fiddly, have me do it with you
once over a screenshare and then you are set forever.

---

## One-time setup

### Step 1 — Install the Claude Code app
Download the **Claude Code desktop app** (Mac or Windows) and sign in with your Claude account.
It is the same account you already use. (No terminal needed, it is a normal app.)

### Step 2 — Get the book folder
Best way: install **GitHub Desktop** (a free, simple app), sign in, and "clone" our book repo
(`clarity-compass-book`) to your computer. That gives you a folder on your machine and a one-click
**Pull** button to grab my latest updates any time.

(If that is a hassle, I can just send you the folder. You will only lose the auto-update button,
and I can re-send when I make changes.)

### Step 3 — Open the folder in Claude Code
In the Claude Code app, open the `clarity-compass-book` folder.

### Step 4 — Tell Claude to set it up
Just type:

> set me up

Claude will install the search tools and build the index for you. Takes about a minute. That's it.
You never touch the terminal.

## Using it

Just talk to Claude normally. It already knows the whole book. Some examples:

- "Read the North chapter and tell me where it drags."
- "Where do I talk about identity? I don't want to repeat myself."
- "Add a story here about ___. Where should it go?"
- "Rewrite this paragraph tighter, keep my voice." (then paste it)

Or use these simple commands:

| Type this | What it does |
|---|---|
| `/find imposter syndrome` | Fast search for those words in the book |
| `/graph what pulls you off course` | Shows how the ideas connect, with chapters |
| `/board` | Runs your full panel of five editors + their consensus |
| `/editor reader` | Runs just one editor (developmental, structural, narrative, line, or reader) |
| `/save` | Saves a snapshot of your work (see below) |
| `/update` | Pulls my latest version of the book and refreshes search |

## Your panel of book editors (your writing tools)

You have a team of five expert editors on call, like having five pros read your book for you. Bring
in whichever fits what you need. In Claude Code you summon one by typing **`/editor`** and its name,
or run the whole panel with **`/board`**. You can also just say it in plain English ("have the reader
editor look at chapter two").

| The editor | What it does | Reach for it when... | Type |
|---|---|---|---|
| **Developmental** | The whole book: big argument, what's missing, what to cut | You want to know if the book as a whole is working, or you finished a big round of writing | `/editor developmental` |
| **Structural** | Pressure-tests the compass framework | You wonder if the directions overlap or have gaps, or North vs. Magnetic North is confusing | `/editor structural` |
| **Narrative** | Your stories and examples | A chapter feels flat, a story runs long, or a section needs a story | `/editor narrative` |
| **Line** | Sharpens sentences, keeps your voice | The ideas are solid but the writing feels clunky | `/editor line` |
| **Reader** | Reads it as a busy entrepreneur | You want to know where a reader leans in, where they'd stop, or if the teaser reveals too much | `/editor reader` |
| **All five + consensus** | The whole panel at once | A periodic gut-check on what matters most next | `/board` |

Every editor is told to be brutally honest, the way you asked. They protect what's working and tell
you straight what isn't.

**For the very end only:** `/polish` is the final cleanup pass (typos, grammar, making it read
publish-ready). Claude will double-check the book is basically done before running it, because
polishing writing you'll still change is wasted effort.

## Saving a snapshot (optional, but handy)

Now and then, after you've made some good edits, Claude may offer to "save a snapshot." You can also
just say **`/save`**. A snapshot is like hitting save with a label on it: it records the book exactly
as it is right now, so you can always look back or undo to that point later. It stays on your own
computer. You never have to type anything technical. Claude does it for you.

Search stays fresh on its own: every time you save a snapshot or pull my updates, the search rebuilds
itself automatically. You never have to think about it.

To send your changes to me, for now just text me the file. Down the road we can set you up to share
back directly if you want.

## Staying in sync with me

When I update a chapter, you get it by either:
- Clicking **Pull** in GitHub Desktop, or just typing **`/update`** inside Claude Code, or
- I re-send you the folder.

Either way, your editors and search instantly work on the newest text. We are always writing off
the same book. Love you.
